write-readme is a Claude Code skill that reads your codebase and writes its README. It puts the run command first, uses your real screenshots, and holds every sentence to a set of anti-AI writing rules before you see the draft.

> This README was generated by write-readme.

## Install

```bash
npx skills add ephemerallyCaden/write-readme -g -y
```

## Usage

```
/readme                  # standard
/readme minimal          # 30-80 lines, essentials only
/readme detailed         # every section the project type supports
/readme --type cli       # override the detected project type
```

It asks at most three questions, shows you the full draft, and writes `README.md` only after you approve. If a README already exists, it can enhance it and keep the sections you wrote by hand.

## What it prioritises

### How to run comes first

The install and run commands sit directly under the title and hero image, ahead of features and architecture. Commands are checked against your build files, so you won't get `npm start` without a start script, `java -jar` without a shaded jar, or `dart run` on a Flutter app.

### It looks the part

It searches the whole project tree for images, including screenshots, test renders and design folders, then looks at each one. If a visual project has no screenshots yet, it offers to capture them (Playwright for web apps, VHS for terminals) or leaves a placeholder that says exactly what to capture.

### It sounds like a person wrote it

The writing rules are adapted from multiple avoid AI writing skill and applied while the draft is written, then checked again before you see it. That means banned words, no section intros that explain what the section covers, and no bold-label feature bullets. Every sentence also has to pass a portability test: if it could appear unchanged in another project's README, it gets rewritten with a fact about yours.
